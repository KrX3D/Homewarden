# Homewarden - project notes

Self-hosted Docker app for a homelab: knows which devices are on, what software
versions they run, what needs updating, and updates individual parts or everything.
Combines what Uptime Kuma (presence), PatchMon (patch status), WUD (image updates),
Komodo (Docker management), Beszel (resource stats), Scrutiny (SMART) and NetAlertX
(network discovery) do, in one tool configured entirely through the GUI.

This file is the working memory for AI agents and contributors. Keep it current: when a
decision is made or changed, update it in the same PR.

## Origin

- Owner: KrX3D. Homelab: Unraid (Docker host, also runs this app), Proxmox with LXCs,
  Raspberry Pis (OctoPi printers, AdGuard Pi), Proxmox Backup Server as an Unraid docker
  that only runs a few hours, UniFi network, Windows machines managed by DeployDeck.
- Several devices are only on sometimes (OctoPi only while printing, PBS a few hours).
- Ansible was tried before and dropped: it needed code/YAML for everything, had no
  state or UI, and setup was hard to figure out. Homewarden must never require writing
  config code. Old playbooks (inactive): `\\192.168.90.114\Scripts\Ansible`.

## Stack

- Go backend, React frontend (Vite) embedded into the binary, one image. Same stack as
  DeployDeck so DeployDeck can later become the Windows integration.
- SQLite via the pure-Go driver `modernc.org/sqlite` (no CGO, easy cross-compiling),
  WAL mode. One file under `/data`, so backing up Homewarden = copying appdata.
- Light and dark mode required, follows the system with a manual override.
- Image: `ghcr.io/krx3d/homewarden`, built by GitHub Actions for linux/amd64 and
  linux/arm64. `latest` + `0.1.<commit count>` on main, semver tags on `v*` tags.
- Optional agent: same repo under `/agent` later, cross-compiled for Pi (ARM), x86 and
  Windows.

## Decisions

### Presence

- Staged, not on/off: Offline -> Reachable (ping/TCP answers, may still be booting)
  -> Ready (real service answers: SSH login works or the API responds, and stays so for
  a settle time, default 60 s, per device) -> scan.
- A scan only starts at Ready. Failed scans retry with backoff.
- Offline devices show "last seen X".

### Connection

- Per device: agentless (SSH, WinRM, native API) or agent, switchable later.
- SSH keys are generated by the app; the user never handles them.
- Least privilege where possible (e.g. sudo rule for apt only instead of full root).
- Secrets encrypted at rest with a master key.

### Updates

- Detection: current version, available version, per component (e.g. OctoPrint core,
  each plugin, OctoPi OS separately).
- Per device/component policy: manual, scheduled, auto, or external trigger (API/MQTT).
  The user decides; the UI warns about consequences ("this restarts the host").
- Busy guards, both kinds, all configurable:
  - built into integrations (OctoPrint: block while a started print job is active,
    including its preheat phase; plain manual heating does not block)
  - generic rules built in the GUI (e.g. container CPU above N%, API returns X).
  - Guard mode per device: block, warn, or ignore. Default for generic: off.
- Optional backup-before-update per device.
- Rollback to a pickable previous tag (Docker) or the pre-update backup/snapshot.
- Changelog shown before updating, "reboot required" flag, EOL OS detection,
  security-flagged updates highlighted.
- Homewarden's own host and Homewarden itself: notify only. A container cannot cleanly
  replace itself, and recreating it outside Unraid's template desyncs the Docker tab.
- Packages inside container images (e.g. nano): shown as info/CVE list only, since
  in-container updates are lost on recreate. For own images (GitHub or local Gitea):
  either open a PR that bumps the base image/package so CI builds a new image, or show
  exact step-by-step instructions. Never push directly.

### Backups

- Separate Backups section: targets (SMB share first), retention, per-device jobs.
- Backup health: last backup age per device, alert when older than N days, PBS results.

### Discovery and onboarding

- Auto-discovery (containers from Unraid/Docker, LXCs/VMs from Proxmox, UniFi client
  list, optional network scan) plus manual adding.
- Discovered devices land in an inbox: Add (then configure) or Ignore. Ignored devices
  are hidden in a list and can be re-added later.
- Onboarding: guided how-to with exact steps per integration, test-connection buttons.
- Optional provisioning per integration (e.g. OctoPrint: restore last backup and
  reinstall plugins). Many integrations will not have it.

### Integrations ("marketplace")

- Core: devices, presence, vault, scheduler, jobs/history, backups, API/MQTT, UI.
- Integrations live in this repo under `integrations/<id>/`, with
  `integrations/index.json` as the catalog that the marketplace shows.
- An integration = manifest (name, icon, version, min core version, settings schema
  the GUI renders as a form, how-to text) + JavaScript run in an embedded sandboxed
  engine (no compiling, no new image per integration).
- Sandbox: a script only gets what the core grants (run a command on this device over
  SSH, call this device's API). This is the supply-chain protection.
- Catalog sources are a setting: GitHub by default, local Gitea can be added.
- Installed integrations are stored in `/data/integrations/<id>/<version>/` and loaded
  from there on every start. Never re-downloaded on boot; updated only when the user
  clicks update, pinned to an exact version, with a diff shown first.
- Built-in copies ship in the image as seed/fallback for offline first start.

### Monitoring extras

- Uptime Kuma monitor types (HTTP keyword/JSON, TCP, ping, DNS, Docker, push,
  MQTT, databases, gRPC), response-time graphs, cert expiry, status pages, maintenance
  windows, groups.
- Komodo/Beszel-style host and container stats (CPU, RAM, disk, network, temps) with
  history; its own section per device.
- SMART disk health (Unraid array, Pi SD cards), disk space warnings.
- New-device-on-network alerts (UniFi client list / scan).
- Docker hygiene: unused images/volumes with cleanup.
- Version history per device, kept 1 year.

### Auth

- LAN only, behind nginx. Never exposed to the internet, no VPN.
- First start: setup wizard creates the first admin (username chosen there). The
  wizard requires a one-time setup token printed in the container log, so nobody else
  on the LAN can claim the instance first.
- Local users, optional TOTP 2FA. OIDC SSO later (one implementation covers Authentik
  and Authelia).
- Roles: built-in Admin, Operator, Viewer plus custom roles with per-permission
  checkboxes, optionally limited to device groups.

### UI

- Device view default: card grid (A), switchable to fleet table (B) and host tree (C)
  via small icons top right. Remembered per user. An "Overview" summary page (counts,
  needs attention, recent jobs) may come later.
- Icon: "Pulse house" variant 6 "Chimney" (house with chimney and a heartbeat line).
  `assets/mark.svg` is the line mark (currentColor), `assets/icon.svg`/`icon.png` the
  app icon (white mark on accent #2f56c9, rounded square). Unraid template points at
  the raw `assets/icon.png` on main.

### Container

- Runs as PUID:PGID, default 99:100 (Unraid nobody:users). Nothing needs root:
  ping works unprivileged in Docker, the Docker socket only needs its group. The
  entrypoint (`docker/entrypoint.sh`) creates the user, adds it to the socket's group,
  chowns `/data` if needed, then drops privileges with su-exec. PUID=0 = run as root.
- Unraid template: `unraid/homewarden.xml`.

## Scope / roadmap

- v1: core + Linux/apt via SSH + Docker + OctoPrint. Manual updates, busy guards,
  OctoPrint backup to SMB before update.
- v2: Unraid, Proxmox/LXC, PBS, schedules, API/MQTT triggers, agent.
- v3: UniFi, Windows (DeployDeck integration), provisioning.
- Later: notifications (Discord, ntfy, Telegram, email, HA), Home Assistant via MQTT
  discovery.

## Workflow

- The initial commit went to `main` directly. Every change after that: new branch + PR
  against `KrX3D/Homewarden` `main`. Never push to main.
- PR descriptions: 2-4 bullet summary, no test plan.
- Never build or commit release artifacts; CI builds the image.
- Code, comments and docs in English. If UI translations are added, keep `en` and
  `de` together.

## Layout

- `cmd/homewarden/` - entry point: opens vault + DB, logs the setup token, serves HTTP
- `internal/store/` - SQLite (modernc, pure Go), migrations in `migrations.go`
  (append only; `PRAGMA user_version` counts them), one connection
- `internal/vault/` - AES-256-GCM for secrets; key from `HOMEWARDEN_MASTER_KEY` or
  `/data/master.key`
- `internal/auth/` - bcrypt passwords (min 10 chars), session tokens (stored as
  SHA-256), TOTP (RFC 6238), setup token, login rate limiter, permission catalog
- `internal/api/` - HTTP API. Every non-GET `/api/` request needs the `X-Homewarden`
  header (CSRF). Errors are `{"error": "<code>"}`; the UI translates `error.<code>`.
  `Server.Authed(perm, h)` and `Server.Handle` let other packages add routes.
- `internal/presence/` - probes (unprivileged ICMP via x/net/icmp "udp4", TCP, HTTP
  <500 = up) and the engine. `Next()` is the pure state machine (unit tested):
  2 missed reach checks = offline; ready needs the ready probe to pass for
  `settleSeconds`. `OnReady` callbacks fire on the transition to ready (scans hook in
  there). History in `presence_events`, pruned after 1 year.
- `internal/discovery/` - ping/port sweep of a CIDR (max 1024 hosts) into the inbox
  (`status=discovered`, `source=scan`, `external_id=ip`).
- `internal/events/` - SSE broker at `/api/events` (`device.state`, `device.seen`,
  `device.changed`, `discovery.*`). Web hook: `web/src/useEvents.ts`.
- Devices: `status` active|discovered|ignored; `parent_id` builds the host tree;
  `presence` JSON {reach, ready, settleSeconds, intervalSeconds}; reach `none` = state
  comes from elsewhere (e.g. container state from its host integration).
- `web/src/extensions.ts` - `deviceSections` (cards on the device page) and
  `settingsTabs`; feature modules in `web/src/features/` push into them and are
  imported once from `main.tsx`.
- `internal/store/credentials.go` + `internal/api/credentials_handlers.go` - vault of
  ssh_key / password / token. Secrets are vault-encrypted, never returned by the API.
  SSH keys are ed25519 generated in-app (or a pasted unencrypted key). A credential
  referenced by any device config field ending in `credentialId` cannot be deleted.
- `internal/sshx/` - SSH dial/run, key generation, TOFU host-key pinning
  (`known_hosts` table keyed by host:port; mismatch = `host_key_changed`, the UI offers
  "trust the new key" which deletes the pin).
- `internal/conn/` - device `config.connection` {method: ssh, port, credentialId,
  user, sudo}. `Exec(..., privileged)` wraps in `sudo -n sh -c` when sudo is on.
  `InstallKey` logs in once with a password (never stored) and appends the public key.
- `internal/web/` - embeds `dist/` (Vite output; only `.gitkeep` is tracked)
- `web/` - React + TypeScript + Vite. `src/i18n/en.json` + `de.json` must always have
  the same keys. Theme/lang/device-view are per-user prefs (`PUT /api/me/prefs`).
- `Dockerfile` - multi-stage, Go cross-compiled per target arch
- `docker/entrypoint.sh` - PUID/PGID handling
- `unraid/homewarden.xml` - Unraid container template
- `assets/` - icon sources and PNGs
- `.github/workflows/docker.yml` - vet/test, then multi-arch image build and push
